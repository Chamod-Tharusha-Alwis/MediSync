## Script: `scripts/seed-platform-data.js`

### Design principles
- Uses the application's own Mongoose models so field encryption and blind indexes apply.
- `--dry-run` is the default: prints counts per collection only, no writes.
- `--confirm` writes. `--remove --batch <id>` deletes only records carrying `seedBatchId`.
- Idempotent: re-run with `--confirm` on an existing batch is a no-op (checks batch marker).
- Never prints personal data (names, NICs, emails) to stdout/logs.
- Reads credentials from `server/.env` (untracked). Fails fast with a clear message if
  MONGO_URI / MONGODB_URI is absent. No localhost fallback.
- Seed scripts must NOT trigger notification emails (use a flag to disable email in env or
  pass a `skipNotifications: true` option to any service call that would send email).
- ML SQLite: not seeded by this script. Public/admin outbreak views read Mongo only.

### Batch marker
Every created document carries `{ seedBatchId: "SEED_2026_11_A" }` as a private field,
excluded from all API serializers. Never shown in any UI or API response.

### Removal
`--remove --batch SEED_2026_11_A` runs dry-run counts first, then deletes only documents
where `seedBatchId === "SEED_2026_11_A"`. Never touches documents without that marker.
Running `--remove` without `--batch` fails with an error.

## Realism constraints

- **Weekday/weekend:** 20% fewer consultations on Saturday/Sunday.
- **Age/sex mix:** plausible Sri Lankan age pyramid (more patients under 15 and over 60).
- **Doctor affiliation:** each doctor is affiliated with a hospital in the same district;
  consultations for that doctor's patients happen in that district.
- **Prescriptions matched to diagnosis:** fever-type diagnoses → paracetamol + ibuprofen;
  infections → amoxicillin or co-amoxiclav; hypertension → amlodipine; diabetes → metformin.
  Choose only from `isPrescribable: true` items in the Drug catalog.
- **Lab orders:** fever/infectious diseases trigger lab orders (CBC, blood culture) ~40%
  of the time; non-infectious diseases ~10%.
- **Dispensing:** ~70% of prescriptions dispensed within 3 days of issue.

## Account design

- **No login** for synthetic patients, doctors, hospitals, pharmacies — set an impossible
  password hash (`$2b$10$XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX` where
  X is replaced by a string that cannot match any bcrypt input).
- **Phone numbers:** no reserved/non-subscriber range has been verified. The
  previous assumption that a plausible local range cannot belong to a subscriber
  is withdrawn. No address or phone delivery may be enabled for synthetic actors.
- **NIC identifiers:** use day-of-year code outside 001–366 and 501–866. Proposed pattern:
  `9999{random6digits}V` for old-format or `{year}9{random7digits}` for new-format NIC
  (where year is 1960–2000; `9` as the day-of-year prefix makes it impossible for a real
  person born on day 900). **NOT APPROVED:** the actual validator at
  `server/src/controllers/patientController.js:45-47` checks format only. The
  proposed old pattern has eleven characters and fails it; the twelve-digit
  pattern passes format but proves no reserved range/collision safety. Seven
  synthetic local checks are recorded in
  `CODEX_RECONCILIATION_LOCAL_CHECKS_20261105.json`. No safe unique identity
  allocation or account-isolation design is claimed qualified.
- **Email addresses:** no concrete operator addresses belong in this plan. Any
  later authorized test recipient must be provided privately at runtime. Existing
  account inventory is NOT VERIFIED here; no credential file was read. Do not
  create email-receiving accounts or trigger delivery.
- **Never modify** the five real role accounts, the operator's test patient, or any record
  without the seed marker.
